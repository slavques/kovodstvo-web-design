# «Место звука»: каталог полевых записей

Готовая автономная страница: `index.html`, `style.css`, `app.js`. Открывается напрямую из файловой системы или через любой локальный статический сервер. Пакеты, сборка, шрифтовые сервисы и внешние запросы не нужны.

## Решение

Применён проверяемый навык `work/publish-kovodstvo-web-design/kovodstvo-web-design/SKILL.md`, разделы 01, 04, 07, 08, 09 и 11. Это каталог, поэтому главная часть — список из шести записей с поиском по названию, месту и среде, переключением среды и открытием сведений.

Рассмотрены три направления: кассетная фонотека, географическая карта и полевой атлас. Выбран атлас: у него есть предметный графический язык, а отсутствие настоящих аудиофайлов и точных координат не требует выдумывать содержимое. Географическая карта могла бы обещать отсутствующие пространственные данные; кассетная фонотека смещала бы внимание с места на носитель.

Узнаваемый приём — ботанически зелёный полевой лист с красной точкой наблюдения, условным рельефом и шестью оригинальными векторными виньетками: лес под дождём, ночной причал, перевал, трамвайное кольцо, двор, камыши. Все SVG написаны для этой страницы. Это иллюстрации, не фотографии мест, не географические данные и не волновые формы аудиофайлов. Условность верхней карты подписана. Системный гротеск, крупная строка заголовка, тонкие горизонтали и спокойные метаданные удерживают архивную плотность.

На узком экране сведения организованы в компактные строки: рисунок, название, место и среда, длительность. Контролы переносятся, поля и кнопки сохраняют удобную высоту. Предусмотрены видимый фокус, переход к каталогу с клавиатуры, `aria-pressed`, счётчик `aria-live`, нативный modal dialog, закрытие и возврат фокуса. Движение ограничено короткими hover-переходами и плавной прокруткой; reduced motion их отключает.

## Реализовано

- Все шесть заданных названий, мест, типов среды и длительностей сохранены без изменения.
- Поиск без учёта регистра с нормализацией «ё/е», пробелов и сочетаний слов. Слова должны находиться в совокупности названия, места и среды.
- Среды: все, лес, вода, горы, город. Фильтр и поиск действуют совместно.
- Текущий счётчик, очистка поиска, пустая выдача и полный сброс.
- Сведения каждой записи: название, номер, место, среда, длительность, явное сообщение об отсутствии аудиофайла.
- Закрытие карточки кнопкой, Escape через нативный dialog и нажатием на фон; возврат к кнопке записи.
- Плеера, кнопок воспроизведения, таймера воспроизведения и фальшивого аудио нет.

## Выполненные проверки

1. `node --check app.js` — синтаксис корректен.
2. `design_audit.py <archive> --json` — два кандидата на проверку: сброс `outline` у поискового поля. В CSS предусмотрен альтернативный видимый фокус всей области поиска через `:focus-within`, цвет рамки и `box-shadow`; остальные контролы получают общий `:focus-visible`. Скрипт не проверяет вычисленные стили и визуальную достаточность этого решения.
3. Выполнен JavaScript в Node VM с минимальной DOM-заглушкой: начальные 6 строк; поиск «КАРЕЛИЯ» → 1; «город» → 2; сочетание «город» + вода → 0; вода без запроса → 2; «Ночной Владивосток» + вода → 1; пустая выдача; сброс → 6; открытие Алтая с длительностью 06:05; закрытие и вызов возврата фокуса; нормализация Ё → е. Все проверки прошли. Это проверка реальной логики исходного JS, не проверка браузерного DOM или клавиатурного поведения.
4. Поиск по исходникам не обнаружил сетевых API, внешних URL, импортов, аудиоэлементов или Audio API. `url(#…)` в SVG ссылается только на локальный узор и маску.
5. При статической оценке ширин передвинут мобильный breakpoint на 850 px, чтобы сумма колонок списка не переполняла промежуточные размеры. Это ещё требует проверки рендера.

## Передача родителю: браузерные сценарии

1. Открыть `index.html`, оценить полный экран и все шесть графических миниатюр на ширинах 1440, 1024, 851, 850, 390, 320 px. Проверить горизонтальный скролл, заголовок, переносы названий, фильтры и карточку.
2. Ввести «КАРЕЛИЯ» — одна запись. Очистить × — шесть. Ввести «город» — две.
3. Выбрать «Вода» — две; ввести «Владивосток» — одна; выбрать «Горы» при прежнем запросе — пустая выдача; нажать сброс — шесть и активный фильтр «Все».
4. Открыть любую запись нажатием на её строку; проверить все метаданные и отсутствие действий проигрывания. Закрыть ×, кнопкой возврата, Escape и фоном. Фокус должен вернуться к записи, прокрутка страницы — восстановиться.
5. Пройти Tab / Shift+Tab: skip-ссылка, каталог, поле, очистка при наличии текста, фильтры и кнопки записей. Проверить удержание фокуса внутри нативного dialog и последовательность чтения скринридером.
6. Включить reduced motion, проверить отсутствие плавной прокрутки и переходов. Отключить JavaScript — показать честное пояснение и текстовый список всех материалов.
7. В Network убедиться, что страница не обращается к внешним адресам.

## Ограничения

По условиям делегированного задания UI-инструменты не применялись: фактический рендер, художественная оценка, клавиатура в настоящем браузере, скринридер, сетевой журнал и физический телефон здесь не проверены. Браузерную проверку проводит родитель. Native `<dialog>` предполагает актуальный браузер. Данные демонстрационные; файлы, даты экспедиций, координаты, авторы и лицензии записей не заданы и не выдуманы. Состояние фильтров существует в текущей странице и не сохраняется после перезагрузки.
