# Исправление формы «Орбита»

Готовый артефакт: `index.html` в этой папке. Открывается как самостоятельный HTML-файл.

Причина потери данных — безусловный вызов `form.reset()` при отправке. В исправленном обработчике он удалён; имя, почта и выбранная роль остаются в полях. Повторная проверка и редактирование доступны. Сообщение теперь честно описывает демонстрационный режим: «В этом примере проверка недоступна. Введённые данные остались в форме.» Успешная отправка не имитируется; запросы на сервер не добавлены.

CSS и вся HTML-разметка до script побайтово совпадают с исходником: фиолетовые токены, Inter, геометрия карточек, тексты и элементы экрана сохранены. Исходный файл не изменён. Никаких зависимостей или постоянного хранения персональных данных не добавлено. Сохранение действует в текущей форме, а не после перезагрузки страницы.

## Фактическая проверка

В Node.js исполнен исходный и исправленный script через `vm` с минимальными двойниками DOM:

- Исходный обработчик воспроизводит сброс заполненных полей.
- Исправленный обработчик отменяет стандартную отправку, сохраняет имя, почту и роль и показывает сообщение о недоступности.
- Повторная отправка сохраняет введённые значения.
- Изменённые имя, почта и роль сохраняются при следующей попытке.
- Вызовы reset отсутствуют во всех исправленных сценариях.
- Проверено побайтовое равенство разметки и CSS до script.

Результат перечисленных проверок: PASS. Это проверка логики обработчика, а не браузерный E2E. Нативная HTML-валидация, клавиатурный сценарий, мобильный/настольный рендер и объявление статуса скринридером здесь не проверялись; просмотр рендера выполняет родительский агент по условиям задания. Backend в примере не подключён.
